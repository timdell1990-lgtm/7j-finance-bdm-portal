Recommended production setup — Azure AI proxy
1. Create an Azure Function (HTTP trigger) called broker-search. 2. Store the OpenAI API key in the Function App setting OPENAI_API_KEY (never in this HTML or a Microsoft List). 3. Configure the function to accept {query, maxResults}, call the OpenAI Responses API with web search, validate the returned broker records, and return a JSON array. 4. Paste the HTTPS function URL into Azure AI proxy endpoint above. 5. Save settings and test in Demo Mode first. The portal will then call the proxy instead of exposing the key. The API-key field below is retained only for legacy/demo use and should be left blank in production.
Azure Function setup instructions
In Azure Portal: Function App → Functions → Create → HTTP trigger. Name it broker-search. Add application setting OPENAI_API_KEY. Restrict CORS to your portal domain. Have the function call the OpenAI Responses API using web search and request up to the received maxResults (never more than 25). Validate email/phone/domain where possible, remove duplicates, and return only JSON objects with name, company, phone, email, website, city, reason. Enable authentication/API Management in production rather than leaving an unrestricted HTTP endpoint.

📘 Leasing / customer onboarding instructions
  1. In Microsoft Entra admin centre open App registrations → New registration.
  2. For a leased SaaS deployment choose Accounts in any organisational directory (Multitenant). Microsoft identifies this option as the model for applications serving multiple organisations.
  3. Add the exact portal URL as a Web redirect URI. Keep the same Application (client) ID for all customer tenants.
  4. Add delegated Microsoft Graph permissions required by the portal, currently User.Read, Sites.ReadWrite.All and Calendars.ReadWrite. Use least privilege and obtain admin consent where required. Microsoft documents Sites.ReadWrite.All as allowing delegated editing/deletion of list items on behalf of the signed-in user.
  5. For each customer, set the Company name, Tenant ID, SharePoint host and site path. For SaaS mode select Multitenant.
  6. Create the portal's Microsoft Lists in the customer's SharePoint site and enter their exact display names under Admin → SharePoint List Sources. Click Test, then Save.
  7. Create BDM Call Guide with: Title, SectionKey, Content (multiple lines), SortOrder, Active, Updated, UpdatedBy. Then use the Call Guide editor to publish/edit sections.
  8. For the strongest outcome-state protection, add an optional Broker List column named WorkflowStateUpdatedAt (Date and Time). The portal uses it to prevent an old NO_PRODUCT audit entry from putting a broker back into Not Suitable after an explicit revert.
  9. Never put a client secret in this HTML. Keep AI secrets in the Azure Function/App settings and use delegated Microsoft sign-in for Microsoft 365 data.

Important: changing tenant/site settings takes effect for the next Microsoft sign-in. The current signed-in session keeps its existing access token.
